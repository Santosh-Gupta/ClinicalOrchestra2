# Dataset sourcing and model-cost snapshot — 2026-10-10

This is a sourcing plan for **forecasting the documented next clinical event**, not an evaluation result. Prices and model lineups change; recheck the linked provider pages before a paid batch. Rates below are direct-provider, standard, uncached text-token prices per **one million input / output tokens** unless a row says otherwise. They exclude tool calls, retries, batch discounts, taxes, and long-context tiers. Alibaba quotes CNY, so its rows must not be compared numerically to USD rows. A listed API ID is not proof that our account can call it.

## What to retain from ClinicalHarness 1

The reusable part is the sibling repo's `ClinicalHarness/docs/source_and_licensing.md` policy: preserve PMID, PMCID, DOI, journal, source URL, license, retrieval time, and an explicit release tier; never treat PubMed or PMC access as a reuse license. The old `NeurologyBM/src/neurologybm/sources.py` registry is a **discovery list**, not a vetted allowlist. It includes high-volume or quality-variable venues and PLOS ONE, whose [current criteria explicitly exclude clinical case reports](https://journals.plos.org/plosone/s/criteria-for-publication). Its June 2026 `NeurologyBM/docs/public/model_cutoff_and_testing_guide_20260621.md` table is stale for the models below. Do not copy its common date gate or model IDs.

The current project already parses PMC JATS and checks article-level CC licenses in [`pmc.py`](../src/clinical_orchestra/pmc.py) and [`licensing.py`](../src/clinical_orchestra/licensing.py). [`fetch_cases.py`](../scripts/fetch_cases.py) now saves the already parsed journal and PMID, but still searches PMC broadly by case-report type, open-access flag and publication window. It does **not** filter a prespecified journal cohort or capture earliest public date. Those are intake tasks before scaling.

## Journal discovery registry

The journal list is a **predeclared discovery cohort**, not a claim that every article is reliable or reusable. Editorial publisher/society, actual case-report scope, public peer-review policy and NLM record are positive signals; none proves a report is free of fabrication. Inspect article type, patient consent, correction/retraction status, reporting completeness and chronology after retrieval. Distinguish **MEDLINE indexing** from PubMed presence through PMC: they are not the same credential.

Do not import a journal merely because it is in the old registry, has a PMC record, or charges an APC. In particular, PLOS ONE is not an active case-report source under its [own criteria](https://journals.plos.org/plosone/s/criteria-for-publication). SAGE Open Medical Case Reports is a real peer-reviewed journal, but its [standard license is CC BY-NC](https://journals.sagepub.com/author-instructions/sco), so it is outside the default public-release pool. A CC BY-NC-only *separate* research set would need an explicit purpose and release policy. Journal names must be matched by stable NLM ID/ISSN/DOI metadata where possible, not loose substring matching.

## Intake and construction sequence

1. **Freeze the sampling frame before reading model outputs.** Choose journal strata, calendar window, search query, target counts, and a deterministic/random sampling seed. Log all retrieved and rejected PMCIDs with reasons. Do not choose a “hard” set from any evaluated model's failures. Include a separate, objectively sampled reference set.
2. **Verify each article.** Require case-report content, article-level CC0/CC BY (CC BY-SA only under the existing explicit policy), and no no-derivatives restriction. Compare PMC JATS license with publisher article page; quarantine disagreement or absent license. Exclude third-party figures/text unless their rights are separately clear. Check DOI/PMID/PMCID duplicates, publication updates and correction/retraction notices.
3. **Record the *earliest public version* date.** Preserve publisher first-online date, PMC date, print date, preprint/version date where found, retrieval timestamp and evidence URLs. A year alone cannot establish post-cutoff status. A report first online before a solver's cutoff is not rescued by a later issue date. If earliest date is unknown, mark temporal eligibility unknown. For a month-only cutoff use the end of that month conservatively, plus a prespecified lag. Disable web/search retrieval for the closed-book baseline.
4. **Gate case quality before LLM construction.** Require a usable chronological narrative, enough information states for at least one prospective question, identifiable action/result/outcome provenance, and patient-level clustering. Record why cases fail. Do not require a surprising outcome as an inclusion rule: that would skew event frequencies.
5. **Run the existing dual chronology + blind alternatives + independent audit pipeline** on a development pilot. Stratify item yield and audit failures by journal, task family and case. The actual event remains a source-reported label, not an optimal-care judgment; low predictability is not automatically a bad item. Inspect leakage, omitted facts, overlapping options and `OTHER`. Keep the untouched test set closed during prompt tuning.
6. **Measure the corpus before scaling.** Report retrieved → rights-eligible → case-complete → constructed → audited → exported, with case counts as well as item counts. Report by journal and family so a high-yield venue does not silently dominate. Treat multiple items from one patient/report as clustered observations.

The knowledge-cutoff screen reduces likely training overlap; it **cannot prove non-exposure**. Providers can have hidden post-training data, preprints, copied cases, search access or moving aliases. For models with undisclosed cutoffs, report temporal status as unknown and keep them out of any claim of a clean post-cutoff test, unless an independently justified release-date lag is explicitly labeled as a weaker proxy. Freeze the solver roster and source policy before assembling the final test cohort.
